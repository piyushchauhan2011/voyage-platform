Kafka concepts in this slice

  • Partition: the message key is the hotel id, so events for one hotel stay ordered.
  • Offset: the consumer records the broker offset for every processed message below.
  • Consumer group: the listener runs under one named group so another consumer can share the same topic later.
  • Retention: Kafka keeps the event log even after this consumer processes it.
  • Replication: production clusters replicate partitions; this local compose file uses one broker, so replication stays conceptual here.
  • At least once: duplicate deliveries are acceptable because processed event ids are stored idempotently.
  • Exactly once: not enabled here; it would require transactional semantics across producer and consumer boundaries.
  • Retries + DLT: exhausted failures are retried, then forwarded to the dead-letter topic for inspection.
